# 简历文本写作规则

## 三套写作体系

### 体系判定

依据 `interview-vault/profile/master.md` 中的 `writing_system` 字段：

| 身份 | 判定条件 |
|------|---------|
| 校招生 | 无全职工作经历（仅实习/校园项目） |
| 社招 0-5 年 | 全职总年限 ≤ 5年 |
| 社招 5 年+ | 全职总年限 > 5年 |

---

## 模块顺序

| 维度 | 校招生 | 社招 0-5 年 | 社招 5 年+ |
|------|--------|-----------|-----------|
| 模块顺序 | 基础信息 → 教育经历 → 实习经历 → 项目经历 → 专业技能 → 荣誉证书 | 基础信息 → 个人简介 → 教育经历 → 工作经历 → 项目经历 → 专业技能 → 荣誉证书 | 基础信息 → 个人简介 → 教育经历 → 工作经历 → 核心项目经历 → 专业技能 → 荣誉证书 |
| 个人简介 | 无此模块 | 有，置顶于教育经历上方 | 有，置顶强化 |
| 教育经历权重 | 最高 | 精简 | 极简压缩 |
| 核心权重 | 教育 + 实习 | 工作经历 | 工作经历 + 核心项目 |
| 页数限制 | 优先 1 页，内容极多放宽至 2 页 | ≤ 2 页 | ≤ 2 页 |
| 证书筛选 | 保留全部 | 过滤市级以下 | 仅保留高权威资质 |

## 项目段生成规则

### 数据来源

从 `interview-vault/projects/proj-{NNN}/full-card.md` 提取：

| 提取内容 | 来源 |
|---------|------|
| 项目名称 + 角色 | metadata + skeleton |
| 核心工作 | stages 中各阶段的 solution.final_design |
| 关键决策 | stages 中有演进脉络的关键转折点（1-2个最重要的） |
| 量化成果 | extracted_indices.metrics（选最有说服力的 2-3 个） |
| 技术关键词 | skeleton.tech_stack + extracted_indices.keywords |

### 压缩规则

每个项目段压缩到 200-280 字：

```
[项目名] | [角色] | [时间段]

项目背景：[1-2句，含业务规模数据]
核心工作：
  · [动作1：具体到这个场景的工作，含技术关键词]
  · [动作2：具体到这个场景的工作]
  · [动作3：关键决策或方案设计亮点]
项目成果：
  · [量化成果1]
  · [量化成果2]
  · [量化成果3（可选）]
```

### 写作要求

- **动词开头**：每条工作用动词起头（负责/主导/搭建/设计/推动...）
- **STAR 精简**：Situation 极简（1句背景），Task 融入 Action，Result 量化
- **删冗余**：删除无信息量修饰语（"深入调研""充分沟通""积极推动"）
- **强化贡献**：突出"你做了什么"，不是"团队做了什么"
- **量化优先**：有数字的放前面，定性描述放后面
- **技术具体**：不说"搭建了 RAG 系统"，说"基于 XX 向量库搭建了 XX 领域的检索增强系统"

## 个人简介规则（社招专属）

### 数据来源

| 来源 | 提供什么 |
|------|---------|
| profile/master.md | 年限、行业主线 |
| 跨项目 evidence | 能力标签 + 证据 |
| 跨项目 metrics | 代表性成果数据 |

### 硬性约束（三行三句）

1. **最多 3 句话**，排版不超过 3 行；简介是"电梯陈述"，不是经历摘要
2. **禁止技术细节词汇**：RAG、LLM、Agent、ASR、NLP、多模态、微调、Tool Calling、向量检索等具体技术名词一律不进简介，只允许"AI 产品 / 智能产品 / AI 解决方案"级别的泛化表述；技术深度由项目段承载，简介只负责让人愿意往下读
   - 注：职能名称（算法团队、研发、测试）不是技术词汇，允许出现
3. **重点体现个人综合素质**，高度概括过往经历最大亮点；不逐条罗列经历，不展开方案细节

### 三句话结构

| 句序 | 功能 | 要点 |
|------|------|------|
| ① 定位句 | 年限 + 领域 + 角色主线 | 用"角色演进"体现经验广度（如"完整经历 A→B→C 三类角色"），不用技术栈体现 |
| ② 亮点句 | 过往最大亮点 1-2 个 | 业务语言 + 最有分量的代表性数字；宁缺毋滥，只放最大的 |
| ③ 素质句 | 综合素质呼应目标岗位 | 统筹推进、跨职能协作、带团队、方法论沉淀等；具体到"怎么协作"而非空泛形容词 |

### 改写示例

❌ 违规（超 3 句、堆技术词、逐项罗列经历）：

```
7年智能语音与AI产品经验，技术主线从传统ASR/NLP延伸至LLM Agent，
完整经历「能力线→解决方案→端到端产品线」三个角色阶段。负责小度
智能家居控制Agent（LLM任务规划+Tool Calling）全流程，擅长把模糊
的语音/AI场景收敛为可评测的指标体系……
```

✅ 合规（3 句、零技术词、突出综合素质与最大亮点）：

```
7 年 AI 产品经验，完整经历能力线、解决方案、端到端产品线三类角色，具备从 0 到 1
到规模化的全周期管理经验。主导的代表性方案在百家企业客户生产落地，并推动覆盖百万级
终端的智能产品完成升级。擅长在目标模糊的复杂场景中建立可评测标准，具备正式带团队、
跨职能协调算法/研发/测试的完整管理经验。
```

### 社招 0-5 年

3 句话（按三句话结构），聚焦：定位 + 最大亮点 + 综合素质。

### 社招 5 年+

3 句话（按三句话结构），亮点句可侧重：规模化成果 + 团队/体系统筹；素质句侧重方法论与管理幅度。

## 话术体系

| 年限 | 推荐动词 | 禁用表述 |
|------|---------|---------|
| 校招 | 参与、协助、落地、优化、验证、调试 | 主导、牵头、带领团队、端到端负责 |
| 0-5年 | 负责、主导、优化、推进、落地、调优、设计 | 牵头、体系化、规模化（除非确实如此） |
| 5年+ | 牵头、端到端负责、搭建体系、规模化、方法论沉淀 | 参与、协助（不应出现在核心项目中） |

---

## 页数控制

严格 ≤ 2 页。内容溢出时按以下顺序精简：

1. 删高冗余语句（修饰词、重复表述）
2. 压缩执行细节（保留决策和成果，删过程）
3. 合并同类条目（相似工作合并为一条）
4. 降低非核心模块权重（教育经历、证书进一步精简）

不删除：核心工作描述、量化成果、关键决策点。
