# 简历文本写作规则

## 三套写作体系

### 体系判定

依据 `interview-vault/profile/master.md` 中的 `writing_system` 字段：

| 身份 | 判定条件 |
|------|---------|
| 校招生 | 无全职工作经历（仅实习/校园项目） |
| 社招 0-5 年 | 全职总年限 ≤ 5年 |
| 社招 5 年+ | 全职总年限 > 5年 |

---

## 模块顺序

| 维度 | 校招生 | 社招 0-5 年 | 社招 5 年+ |
|------|--------|-----------|-----------|
| 模块顺序 | 基础信息 → 教育经历 → 实习经历 → 项目经历 → 专业技能 → 荣誉证书 | 基础信息 → 个人简介 → 教育经历 → 工作经历 → 项目经历 → 专业技能 → 荣誉证书 | 基础信息 → 个人简介 → 教育经历 → 工作经历 → 核心项目经历 → 专业技能 → 荣誉证书 |
| 个人简介 | 无此模块 | 有，置顶于教育经历上方 | 有，置顶强化 |
| 教育经历权重 | 最高 | 精简 | 极简压缩 |
| 核心权重 | 教育 + 实习 | 工作经历 | 工作经历 + 核心项目 |
| 页数限制 | 优先 1 页，内容极多放宽至 2 页 | ≤ 2 页 | ≤ 2 页 |
| 证书筛选 | 保留全部 | 过滤市级以下 | 仅保留高权威资质 |

## 项目段生成规则

### 数据来源

从 `interview-vault/projects/proj-{NNN}/full-card.md` 提取：

| 提取内容 | 来源 |
|---------|------|
| 项目名称 + 角色 | metadata + skeleton |
| 核心工作 | stages 中各阶段的 solution.final_design |
| 关键决策 | stages 中有演进脉络的关键转折点（1-2个最重要的） |
| 量化成果 | extracted_indices.metrics（选最有说服力的 2-3 个） |
| 技术关键词 | skeleton.tech_stack + extracted_indices.keywords |

### 压缩规则

每个项目段压缩到 200-280 字：

```
[项目名] | [角色] | [时间段]

项目背景：[1-2句，含业务规模数据]
核心工作：
  · [动作1：具体到这个场景的工作，含技术关键词]
  · [动作2：具体到这个场景的工作]
  · [动作3：关键决策或方案设计亮点]
项目成果：
  · [量化成果1]
  · [量化成果2]
  · [量化成果3（可选）]
```

### 写作要求

- **动词开头**：每条工作用动词起头（负责/主导/搭建/设计/推动...）
- **STAR 精简**：Situation 极简（1句背景），Task 融入 Action，Result 量化
- **删冗余**：删除无信息量修饰语（"深入调研""充分沟通""积极推动"）
- **强化贡献**：突出"你做了什么"，不是"团队做了什么"
- **量化优先**：有数字的放前面，定性描述放后面
- **技术具体**：不说"搭建了 RAG 系统"，说"基于 XX 向量库搭建了 XX 领域的检索增强系统"

## 个人简介规则（社招专属）

### 数据来源

| 来源 | 提供什么 |
|------|---------|
| profile/master.md | 年限、行业主线 |
| 跨项目 evidence | 能力标签 + 证据 |
| 跨项目 metrics | 代表性成果数据 |

### 社招 0-5 年

3-4 句话，聚焦：岗位匹配度 + 业务能力 + 核心优势 + 工作特质

```
X年XX行业产品经理经验，聚焦XX领域的AI产品落地。独立负责XX产品线，
完成从0到1的[代表性成果]。擅长[核心能力1]和[核心能力2]，
[代表性量化数据]。
```

### 社招 5 年+

3-5 句话，聚焦：行业经验 + 方法论 + 项目统筹 + 团队 + 价值产出

```
X年XX行业经验，X年AI产品落地经验。主导搭建XX体系/流程/团队，
覆盖[业务范围]。沉淀了[方法论描述]，带领X人团队完成[规模化成果]。
[代表性量化数据]。
```

## 话术体系

| 年限 | 推荐动词 | 禁用表述 |
|------|---------|---------|
| 校招 | 参与、协助、落地、优化、验证、调试 | 主导、牵头、带领团队、端到端负责 |
| 0-5年 | 负责、主导、优化、推进、落地、调优、设计 | 牵头、体系化、规模化（除非确实如此） |
| 5年+ | 牵头、端到端负责、搭建体系、规模化、方法论沉淀 | 参与、协助（不应出现在核心项目中） |

---

## 页数控制

严格 ≤ 2 页。内容溢出时按以下顺序精简：

1. 删高冗余语句（修饰词、重复表述）
2. 压缩执行细节（保留决策和成果，删过程）
3. 合并同类条目（相似工作合并为一条）
4. 降低非核心模块权重（教育经历、证书进一步精简）

不删除：核心工作描述、量化成果、关键决策点。
