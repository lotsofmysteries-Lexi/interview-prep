# 面试口述版生成规则

## 目标

将项目档案转化为口语化的"怎么讲"版本，让用户能自然地在面试中讲出来。

## 数据来源

| 来源 | 提供什么 |
|------|---------|
| skeleton | 项目名、角色、时间段、一句话定位 |
| stages.solution | 各阶段方案本体（主叙事） |
| stages.evolution_trail | 演进脉络（关键转折） |
| extracted_indices.metrics | 量化成果 |

## 口述版结构

每个项目生成两个版本：

### 1.5 分钟版（主力版）

```
开头（10秒）：一句话说清楚你做了什么
  "我在XX公司做了一个XX产品，核心是解决XX问题。"

中段（60秒）：你做了什么 + 关键决策
  "我负责的是XX部分。方案上，我们最终采用了XX架构..."
  "中间有个关键转折是XX，一开始我们试的是XX，发现XX问题，所以调整成了XX..."
  "数据方面，我们XX..."

收尾（20秒）：成果 + 一句反思
  "上线后XX指标从XX提升到XX。"
  "如果重新做的话，我会在XX方面做不同的选择。"
```

### 速记要点版（电梯版）

```
项目：[一句话定位]
核心方案：[最终方案的一句话概括]
关键决策：[最有说服力的一个技术取舍]
数据：[最硬的2-3个数字]
一句话反思：[如果重新做会改什么]
```

## 写作要求

| 维度 | 要求 |
|------|------|
| 语气 | 口语化，能直接说出来。不用书面语，不用"本人""该项目" |
| 节奏 | 有起承转合。开头定调 → 中间讲方案和转折 → 收尾讲成果 |
| 具体 | 每个关键点都有具体的名词（技术名/产品名/数字），不泛泛而谈 |
| 自然 | 不像在背书。用"其实""后来发现""当时的想法是"等口语连接词 |
| 时长 | 1.5 分钟版按 250-300 字控制（中文口述约 200 字/分钟） |

## 用户参与

口述版需要用户参与调整：

1. **生成初版** → 展示给用户
2. **用户试读**：用户自己读一遍，标出不顺畅的地方
3. **调整语气**：根据用户反馈调整措辞和节奏
4. **最终确认**：用户能自然讲出来为止
