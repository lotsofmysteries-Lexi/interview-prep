# 面试模拟规则

## 模拟模式

### 标准模式

模拟一场 40-60 分钟的完整面试：

```
1. 开场寒暄（1分钟）
2. 自我介绍（3分钟）
3. 项目深挖（20-30分钟，1-2个项目）
4. 技术/方法论追问（10分钟）
5. 行为面/情景面（5-10分钟）
6. 候选人反问（5分钟）
```

### 追问练习模式

针对特定项目的深度追问：

```
选择一个项目 → 面试官追问 3-5 轮
每轮追问基于上一轮回答继续深入
直到候选人答不上来或追问自然结束
```

### 压力面模式

高强度、挑战性追问：

```
面试官会：
  - 质疑数据的真实性（"这个数字是怎么算的？"）
  - 挑战技术选型（"为什么不用 XX？XX 不是更好吗？"）
  - 追问失败经验（"有什么做得不好的？"）
  - 测试应变能力（"如果XX怎么办？"）
```

## 面试官行为规则

### 基于 vault 数据的追问

```
已知问题测试：
  从 qa-bank.md 中选取追问预埋
  检查候选人是否能回答到预设的 answer_points
  如果回答偏离，追问引导回来

未预料问题测试：
  基于项目档案，但从预埋之外的角度追问
  测试候选人对项目的真实理解深度
  如果候选人答不上来，记录为"应变盲区"
```

### 基于 JD 的定向追问

如果有 JD 匹配报告（`jd-match/` 目录存在）：

```
重点追问 JD 匹配中标记为"部分匹配"和"未匹配"的能力：
  - "你有 XX 经验吗？"（测试迁移叙事）
  - "JD 要求 XX，你怎么理解？"
```

### 追问深度控制

| 追问强度 | 追问层数 | 适用场景 |
|---------|---------|---------|
| 标准 | 2-3 层 | 标准模式 |
| 深入 | 3-5 层 | 追问练习 |
| 压力 | 4-6 层 | 压力面模式 |

追问层数 = 从一个问题开始连续追问的深度。

## 交互格式

### 面试官提问

```
🎤 面试官：[问题]
```

### 用户回答后的反馈

每轮回答后，提供即时反馈（可选开启/关闭）：

```
📝 即时反馈：
  ✅ 优点：[回答中做得好的地方]
  ⚠️ 改进：[可以更好的地方]
  💡 建议话术：[推荐的回答方式]

  参考答案（来自你的档案）：
  [qa-bank 中对应的 answer_points]
```

## 模拟结束后的总结

```
面试模拟总结
─────────────────────────────────────────

总体评分：B+

按维度评分：
  项目深度：A（追问3层都能答出来，细节丰富）
  技术理解：B（方案能讲清楚，但替代方案对比不够充分）
  逻辑表达：A-（结构清晰，偶尔有跑题）
  应变能力：B-（预料之外的问题回答偏泛）
  数据支撑：A（量化数据充分，且能解释计算方式）

暴露的盲区：
  1. [具体盲区1，定位到项目/阶段]
  2. [具体盲区2]

建议下一步：
  1. 补充 [具体内容] 的准备
  2. 练习 [具体场景] 的应变
  3. 重新生成 [项目X 阶段Y] 的追问预埋
─────────────────────────────────────────
```

## 与其他 skill 联动

| 发现 | 触发 |
|------|------|
| 答不上来的问题 | → 建议补充到 qa-bank（interview-qa skill） |
| 暴露的知识盲区 | → 建议补充项目档案（interview-prep skill Phase 3） |
| 话术不顺畅 | → 建议重新生成口述版（interview-qa skill） |
