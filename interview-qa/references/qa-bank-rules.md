# QA 库生成规则

## 数据来源

QA 库是从 vault 中自动汇集的，不需要重新生成：

```
每个项目的 full-card.md → extracted_indices.qa_bank
每个阶段的 probing_prep（追问预埋）
```

## 汇集与组织

### 按项目分组

```
项目1：[项目名]
  阶段1（立项/业务价值）—— 追问强度：极高
    [方案类] Q: ...  A: ...
    [决策类] Q: ...  A: ...
    [落地类] Q: ...  A: ...
    [反思类] Q: ...  A: ...
  阶段4（方案设计）—— 追问强度：极高
    [方案类] Q: ...  A: ...
    ...

项目2：[项目名]
  ...
```

### 按追问类型视图

提供另一种组织方式，便于按类型复习：

```
方案类追问（"你做了什么？怎么运作？"）
  [项目1-阶段1] Q: ...  A: ...
  [项目1-阶段4] Q: ...  A: ...
  [项目2-阶段4] Q: ...  A: ...

决策类追问（"为什么这么做？考虑过什么？"）
  ...

落地类追问（"花了多久？几轮？"）
  ...

反思类追问（"如果重新做会怎么改？"）
  ...
```

## 答案质量规则

答案必须满足以下标准：

| 维度 | 要求 |
|------|------|
| 第一人称 | 用"我"讲述，不用"该项目""团队" |
| 引用具体细节 | 引用项目中的具体数据、方案名、技术选择 |
| 可追问 | 答案本身可以被继续追问至少 1-2 层 |
| 不矛盾 | 同一项目不同阶段的答案之间不矛盾 |
| 不通用 | 不能用在别的项目上也成立的泛泛回答 |

## 高频追问补充

除了各阶段预埋的追问，额外补充以下高频面试追问：

| 问题 | 回答来源 |
|------|---------|
| "这个项目最大的挑战是什么？" | 从演进脉络中选最有张力的转折点 |
| "你在项目中最大的贡献是什么？" | 从方案本体中选最核心的设计决策 |
| "如果重新做会怎么改？" | 从反思类追问中选最有深度的 |
| "项目的量化成果？" | 从 extracted_indices.metrics 中选 |
| "团队怎么协作的？" | 从团队构成 + 交付模式推演 |

```markdown
## 高频通用追问

> [引用项目1/阶段X的演进脉络]

...
```
