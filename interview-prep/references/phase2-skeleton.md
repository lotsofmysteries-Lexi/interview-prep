# Phase 2: 一页纸骨架（每项目×1）

## 目标

基于 Phase 0 画像 + Phase 1 场景，为每个项目生成一页纸骨架。所有项目的骨架全部出齐后，统一做跨项目一致性复核。

---

## 骨架生成

### 输入

| 来源 | 提供什么 |
|------|---------|
| Phase 0 画像 | 年限、行业、交付模式、角色基调 |
| Phase 1 场景 | 场景名、差异化角度、技术时代 |
| 蓝图 | 该项目的时间段、技术栈约束 |
| calibration-rules.md | 校准规则 |

### 语言原则：业务先行

骨架的读者是面试官（可能是业务方、HR、或技术负责人），不是工程文档的读者。

1. **业务价值是主干**：每个项目骨架先讲"解决了什么业务问题、带来了什么收益"，技术是手段不是标题
2. **技术词必须有业务翻译**：出现技术术语时，必须在同一句或紧随其后用业务语言解释它在这个场景中做了什么。例：
   - ❌ "使用 LangGraph 编排 Multi-Agent 系统"
   - ✅ "拆成两个智能体协作——一个负责理解需求拆任务，一个负责看图匹配物料（LangGraph 编排）"
3. **项目名称以业务场景命名**：不用"XX AI 系统"，用"给谁做什么"的格式。例：
   - ❌ "Multi-Agent 智能识别系统"
   - ✅ "智能选材与设计协同平台"

### 生成规则

按 `schemas/project-skeleton.md` 的字段逐一生成：

1. **项目名称**：具体、有行业属性，以业务场景命名，不用"XX AI 系统"这种技术先行的通用名
2. **一句话定位**：≤30字，说清楚"给谁做""解决什么业务问题"，技术可提可不提，提则必须服务于业务理解。例：`给建材供应链做"图纸秒级转报价"的智能协同平台`（"秒级转报价"是业务价值，"智能协同"暗示 AI 但不堆术语）
3. **时间周期**：必须与蓝图中的时间段一致
4. **业务背景**：
   - `why_do_it`：从行业实际出发，含业务规模数据（处理量/人员数/频次）
   - `why_ai`：用业务语言论证为什么这个场景非 AI 不可——核心难点是什么（如"规则写不完、人工又慢又贵"），AI 能力怎么匹配这个难点。禁止用"提升效率""降低成本"等泛化表述，也禁止裸列模型名/框架名
5. **项目目标**：
   - 业务目标含具体数值
   - AI 目标含具体指标和数值预期
6. **角色**：必须与年限→叙事视角表一致
7. **交付模式**：继承画像，可按项目微调，描述具体的执行分工
8. **技术栈**：必须与时间线→技术栈匹配表一致
9. **团队构成**：含角色和人数，与公司体量匹配
10. **量化预期**：至少 2-3 个指标，含 before/after/improvement

### 输出格式

```yaml
项目名称: [具体名称]
一句话定位: [≤30字]
时间周期: YYYY.MM - YYYY.MM
所在公司: [脱敏名称]

业务背景:
  为什么要做: [含业务规模数据]
  为什么用AI: [场景的 AI 适配性论证]

项目目标:
  业务目标: [含具体数值]
  AI目标: [含指标和数值预期]

你的角色: [基于年限校准]
交付模式: [执行分工描述]

技术栈: [与时间线匹配]
团队构成: [角色×人数]

预期量化成果:
  - [指标1]：[before] → [after]（[improvement]）
  - [指标2]：[before] → [after]（[improvement]）
  - [指标3]：[描述性成果]
```

### 用户确认

```
这是 [项目名] 的一页纸骨架，请检查：

[骨架内容]

你可以修改任何字段。确认后我们继续下一个项目的场景选择。

⚠️ 注意：所有项目的骨架全部完成后，我会做一次跨项目统一复核。
```

## 统一复核（所有骨架出齐后触发）

### 触发条件

当蓝图中规划的所有项目都完成了骨架生成且用户确认后，自动触发统一复核。

### 复核内容

按 `schemas/consistency-check.md` 的维度逐一检查：

1. **输出跨项目对比表**：

```
项目    时间线          行业        技术栈      角色          关键指标
──────────────────────────────────────────────────────────────────
项目1   YYYY.MM-MM     XX行业     [技术A]     [角色A]       [指标A]
项目2   YYYY.MM-MM     XX行业     [技术B]     [角色B]       [指标B]
项目3   YYYY.MM-至今   XX行业     [技术C]     [角色C]       [指标C]
```

2. **逐维度校验结果**：

```
✅ 时间线：无冲突
✅ 行业：一致（XX行业）
✅ 技术栈：自然递进
✅ 角色：成长趋势明显
⚠️ 指标：项目1和项目2都用"准确率"，请确认是否同一口径
```

3. **用户确认**：

```
以上是所有项目的一致性复核结果。

[如有警告] 有以下需要你确认的点：
- [警告1的具体说明]
- [警告2的具体说明]

确认后，我会先出一版简历框架，然后逐个项目生成全量细节。
```

## 触发简历框架

统一复核通过后，**在进入 Phase 3 之前**，先输出简历框架。

### 骨架阶段能出的内容

| 内容 | 来源 |
|------|------|
| 简历整体结构（板块 + 排列顺序） | 写作体系 + 年限 |
| 个人简介方向（职业主线初稿） | 行业线索 + 跨项目主线 |
| 项目列表和排序 | 蓝图中的项目序列 |
| 教育经历、基础信息 | Phase 0 画像 |

### 骨架阶段出不了的内容（占位）

| 内容 | 需要等什么 |
|------|-----------|
| 每个项目的详细项目段 | Phase 3 全量生成 |
| 个人简介定稿 | 全量生成后的能力证据 |
| 技能清单 | Phase 4 自动提取 |
| HTML 精排版 | 所有文本内容完成后 |

### 简历框架输出

```
简历框架（骨架版）
─────────────────────────────────────────
[姓名] | [手机] | [邮箱]

个人简介（方向稿，全量完成后定稿）
  X年XX行业产品经理经验，聚焦XX领域的AI产品落地...
  [待补充：核心能力证据、代表成果数据]

项目经历
  项目1：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]
  项目2：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]
  项目3：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]

教育经历
  [学校] | [专业] | [学历] | [毕业年份]

技能清单
  [占位：Phase 4 入库后自动提取]
─────────────────────────────────────────
```

## Phase 2 完成条件

| 条件 | 说明 |
|------|------|
| 所有骨架已生成 | 蓝图中规划的每个项目都有骨架 |
| 所有骨架用户已确认 | 用户逐个确认或修改后确认 |
| 统一复核通过 | 跨项目一致性无硬约束违规 |
| 简历框架已输出 | 用户看过框架（不需要确认，仅展示） |

完成后，进入 Phase 3（逐个项目生成全量细节）。
