# 交互协议（HITL 确认点注册表）

> 背景：v1 实测中出现四类 HITL 失稳——完全跳过（项目 2/3 全量零确认）、形式漂移（骨架确认被塞进选项打包）、时机漂移（低置信度确认拖到事后）、环节蒸发（下游 skill 未加载）。
> 本协议把确认环节从"散文描述"升级为**结构化注册表**：每个确认点有 ID、时机谓词、合法形式、skip 策略。**漏发即违规，跳过必须声明，全程可审计。**

## 执行规则（强制）

1. **注册表即事实源**：确认点只能按下表触发，不得自行增删改。各 phase 文档中的确认描述与注册表冲突时，以注册表为准
2. **三种合法形式**：
   - `A` = AskUserQuestion 选项打包（单次 ≤4 问）
   - `T` = 文本展示全文 + 等待用户回复（逐段确认的默认形式，禁止用 A 代替）
   - `S` = 输出后主动邀请选区/段落反馈
   - 形式绑定不可更改，唯一例外：A 工具不可用时降级为 T，并在输出中注明
3. **进度指针**：每次 HITL 输出顶部必须带进度块（当前位置 / 已完成 / 剩余确认点），格式：
   ```
   📍 Phase 3·项目1（2/4 确认）｜已完成：CP-03 ✅ CP-04×3 ✅｜本步：CP-07｜剩余：CP-08、CP-09
   ```
4. **批量授权语义边界**：用户显式说出"全部确认 / 直接继续 / 剩下的不用问了"类语句时，授权范围 = **当前项目的后续同级别或更低级别 CP**；跨项目不继承；`never` 级 CP 不受任何授权影响
5. **跳过必须声明**：每次 SKIP 在输出中加一行 `⏭ 已跳过 CP-XX（依据你的批量授权）`，并写 log 事件 `hitl_skipped`
6. **违规自查**：进入下一个 CP 前，自查上一 CP 状态（fired / skipped+声明）；发现未触发且未声明的历史 CP → 补触发并说明

## skip_policy 取值

| 值 | 含义 |
|----|------|
| `never` | 任何情况必须触发，批量授权不可豁免 |
| `user_explicit` | 仅用户显式批量授权可跳，跳过必须声明 + 记 log |
| `auto` | 默认执行但无用户回复也可继续（INFO 级展示） |

## 与审计的闭环

- 每个 CP 的触发/跳过写 usage-log 记录点：`{"event":"hitl_fired","cp":"CP-06"}` / `{"event":"hitl_skipped","cp":"CP-06","reason":"batch_authorization"}`
- 会话收尾统计：`预设确认点 N ｜ 实际触发 M ｜ 声明跳过 K ｜ 无声明漏发 X`——**X 必须为 0**，不为 0 时在 log 改进信号字段单列并当场向用户说明
