# 售前交付/行业方案类 QA（Q-PS）

> 覆盖客户沟通、POC 验证、方案设计、招投标、交付管理与定制化平衡类面试题；回答框架需用个人 vault 中的客户项目事实填充。

### Q-PS-001：假设你负责 B 端产品，客户总是提出高投入的个性化设计，你会怎么做？
- 变体问法: "做项目时如何平衡和筛选需求？"、"你的方案与客户需求冲突时如何处理？"
- tags: [customization, b-end, expectation-management]
- 回答框架:
  1. 先判断需求本质：深挖背后真实业务场景，判断真伪与是否真个性化不可复用；PM 应输出更优方案引导客户，而非被客户的方案牵着走
  2. 双轨承接：行业通用需求回产研做抽象化标品设计，对可复用性与经营结果负责；个性化需求用最小成本保质交付，尽量由交付团队承接不占产研资源
  3. 经营评估：按项目重要紧急度、成本、资源综合应对；个性化交付按成本收费，纳入需求池管理形成迭代策略
  4. 项目管理：协调商务/售前/交付对齐口径与客户预期；超合同范围走商务流程；频繁需求引导客户按优先级分批落地，必要时上报风险做高层沟通
- 融合钩子: full-card 方案细节

### Q-PS-002：你做的产品可复用性怎么样？有没有复用到其他客户，还是专门为客户定制的？
- tags: [reusability, standardization, b-end]
- 回答框架:
  1. 表明产品视角：产品按产品化规划，需求虽从共创客户输入，但经营模式是打造标品、以项目形式落地
  2. 设计方法：客户需求 → 拆分个性化与行业标准需求 → 个性化最小成本实现、行业标准拉回产研做通用抽象设计（考虑架构、商业化、竞争力、版本规划）
  3. 商业逻辑：个性化赚交付的人头辛苦费，标准化形成产品持续迭代赚规模化的钱
  4. 演进路径：项目制起步的需求在多客户重复出现且市场机会大时转化为产品，集中资源打造核心竞争力与护城河，对商业结果负责而非项目交付负责
- 融合钩子: master 骨架一览

### Q-PS-003：需要配合售前给客户演示，如何说服一家正在使用竞品的客户购买我们的产品？
- tags: [presale, competitive, persuasion]
- 回答框架:
  1. 策略红线：不只讲功能，按功能→商业→服务层层递进；不贬低竞品、不打价格战、不过度承诺（配能力边界+演进路线）
  2. 产品差异价值：聚焦竞品未满足的核心痛点讲差异化优势，前提是竞品分析准备到位
  3. 商业模式：提供更灵活的模式（如基础费用+效果分成、定制 License+分润）降低迁移成本
  4. 服务体验：免费数据迁移保障业务不断档、专属响应承诺、增值服务
  5. 标杆案例：用替换掉竞品的客户案例与量化收益做示范效应
- 融合钩子: full-card 咬合总账

### Q-PS-004：客户已购 SaaS 轻量版的若干功能模块，后续要增购或减少功能，你作为产品经理要做些什么？
- tags: [saas, modular-design, permission]
- 回答框架:
  1. 定性：这是"配置变更"，本质是模块权限与数据隔离问题，不是让研发改代码
  2. 动态模块管理机制：每个模块有唯一 ID、依赖关系与开关配置，配置表驱动启停，无需写死逻辑
  3. 权限与功能解耦：模块开关与使用权限由权限系统+配置控制；数据隔离要处理（关停后数据保留/迁移/备份策略防误删）
  4. 推进标准化：把模块启停做成平台机制，由客户成功/实施在后台操作，不占用研发资源
  5. 用自己项目举例：客户加购新模块后配置即生效、体验无缝的完整流程
- 融合钩子: full-card 方案细节

### Q-PS-005：你从一个招标文件背景里面能挖掘出什么信息？
- tags: [bidding, to-g, requirement-mining]
- 回答框架:
  1. 明示信息：通读项目背景、采购需求、技术要求、评标方法、实施周期，判断项目类型（平台建设/大模型应用/Agent）、建设范围（子系统数/单位数/周期/试点还是全域）、是否已指定技术路线或厂商偏好
  2. 隐藏信息：强调"合规可控""国产化替代"指向信创与私有化；强调"快速上线"指向老系统增量增强而非推倒重建
  3. 机会挖掘：甲方只定底座不定场景时，乙方需提供"场景建议+价值提炼+落地方案"；结合行业 know-how 从业务痛点提炼高价值场景
  4. 案例收尾：从模糊需求中提炼出具体落地场景并转化为方案核心功能，获得认可中标
- 融合钩子: full-card 方案细节

### Q-PS-006：AI 在 xx 行业有哪些落地场景和应用？
- tags: [industry-scenarios, vertical-ai, trends]
- 回答框架:
  1. 结构：先列行业大类的业务领域，每个领域下给具体应用场景，最后讲趋势
  2. 场景举例（以证券为例）：投研（智能投研助手做市场分析与研报解读）、投顾（个性化理财规划）、风控（财务风险预警）、运营（智能客服与投教）
  3. 趋势收尾：Agent 是落地趋势——多模态融合、端到端任务执行、多智能体协同、订阅式付费等商业模式变化
  4. 面试前必须按目标公司所属行业准备对应版本，最好能结合自己项目经验佐证
- 融合钩子: master 骨架一览

### Q-PS-007：在业务需求不缺的情况下，如何提高 AI 应用的交付效率和质量？
- tags: [delivery-efficiency, standardization, closed-loop]
- 回答框架:
  1. 三板斧总述：选对场景、流程标准化、数据闭环
  2. 选场景：优先数据齐全、流程清晰、能快速验证闭环的任务（输入输出明确、易定位问题），先跑通能力链路再复制，降低试错成本
  3. 标准模块化：把 Agent 业务链路拆成固定模板（意图识别→参数提取→接口调用→回答生成），相似任务只替换接口与参数格式，工程算法不重复开发
  4. 数据闭环：上线后埋点+日志+用户反馈定位 badcase，重点看意图识别、调用、回答准确性；用大模型自动筛 badcase 定向优化
  5. 成果量化：准召率与转人工率的迭代改善作为交付质量证明
- 融合钩子: full-card 咬合总账
