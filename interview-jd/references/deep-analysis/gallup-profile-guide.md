# 盖洛普风格动态求职侧写指南

## 概述

本文档定义了求职分析Skill中用户偏好Profile的设计框架。参考CliftonStrengths（盖洛普优势识别器）的四大领域模型，适配求职场景，构建一个**渐进式、可校准的动态人物画像系统**。

核心设计原则：
- **低门槛启动**：首次填写只需回答3-5个开放式问题，不需要打分或复杂自评
- **渐进式丰富**：每次JD分析后基于当前JD语境提2个引导性问题，约15次完整覆盖30条题库
- **反馈驱动校准**：系统推断 vs 用户反馈的持续对齐，画像随使用越来越准

## 四大领域（求职场景适配）

### 一、影响力域 (Impact)

**核心问题**：你在工作中是否倾向于影响他人、推动事情发生？

求职场景下的表现维度：

| 子维度 | 高倾向表现 | 低倾向表现 |
|--------|-----------|-----------|
| 说服表达 | 善于向他人（客户/同事/领导）阐述观点、争取认同 | 更倾向于用数据/文档说话，不喜欢"推销"自己的观点 |
| 主导意愿 | 主动掌控局面、推动决策 | 乐于配合执行，不急于站出来主导 |
| 舞台感 | 在演示/汇报/公开场合能自然发挥 | 公开表达消耗能量，更享受幕后工作 |
| 结果导向的影响力 | 影响力来自实打实的成果和业绩 | 影响力来自专业深度和信任积累 |

### 二、关系建立域 (Relationship)

**核心问题**：你在工作中与人连接的方式是什么？

| 子维度 | 高倾向表现 | 低倾向表现 |
|--------|-----------|-----------|
| 共情协作 | 天然关注他人的情绪和需求，团队润滑剂 | 关注任务本身多于人际感受，直来直去 |
| 深度信任 | 倾向于建立少数深层关系，重视一对一沟通 | 广泛但浅层的连接，善于跨团队协作网络 |
| 团队融入偏好 | 需要强烈的归属感和团队氛围 | 可以独立工作，团队是工具而非情感依赖 |
| 冲突处理方式 | 先照顾情绪再解决问题 | 直接面对分歧，就事论事 |

### 三、战略思维域 (Strategic)

**核心问题**：你如何吸收信息、形成判断？

| 子维度 | 高倾向表现 | 低倾向表现 |
|--------|-----------|-----------|
| 分析深度 | 喜欢深入钻研一个问题到底 | 快速抓要点，不纠结细节 |
| 全局视野 | 自然从宏观角度看事情，关注趋势和方向 | 聚焦具体执行，逐步理解全貌 |
| 学习方式 | 系统性学习，建立知识框架 | 在做中学，边干边学 |
| 决策依据 | 数据+逻辑推演优先 | 直觉+经验优先，快速试错 |

### 四、执行力域 (Execution)

**核心问题**：你把想法变成行动的方式是怎样的？

| 子维度 | 高倾向表现 | 低倾向表现 |
|--------|-----------|-----------|
| 目标驱动 | 设定清晰目标后高度自律推进 | 需要外部节奏和deadline驱动 |
| 纪律性 | 建立并遵守系统和流程 | 灵活应变，流程感弱 |
| 责任感范围 | 对结果有强烈的个人担当意识 | 团队责任共担，不过度个人化 |
| 交付节奏偏好 | 稳定可持续的长跑节奏 | 阶段性冲刺，需要变化和新鲜感 |

## 渐进式题库（30条）

每次JD分析结束后，根据本次JD的特征从以下题库中选择**最相关的2个问题**提问。选择逻辑：问题应与当前岗位类型的核心特征相关联，让用户的回答能直接服务于后续同类岗位的分析精度。

### 影响力域（8题）

1. 这个岗位上你需要经常向别人（客户/内部）解释AI相关的概念。你觉得这种"把复杂东西讲清楚"的事情，是让你觉得有成就感还是更多是消耗？
2. 回想一下过去的工作经历，有没有哪个时刻是你主动站出来推动了一个决定或者改变？当时的感觉怎么样？
3. 如果一个项目需要你去做一次正式的方案汇报，你的第一反应是什么？兴奋期待还是想找理由推掉？
4. 你更习惯哪种说服方式——用数据和案例理性论证，还是先建立信任关系再慢慢影响？
5. 在团队讨论中，你是那种会积极发表意见的人，还是更倾向于听完大家再说？
6. 如果让你选，你更希望你的工作成果被评价为"专业靠谱"还是"有领导力/影响力"？
7. 面对一个不确定的方案，你更倾向于先把它想清楚再动手，还是先动起来在过程中调整？
8. 当你和别人观点不一致的时候，你通常会怎么做？坚持说服还是先听听对方的？

### 关系建立域（7题）

9. 上一个让你觉得"团队氛围很好"的团队是什么样的？什么让你有这种感觉？
10. 工作中遇到困难时，你更倾向于自己琢磨解决，还是找人聊一聊？
11. 你觉得"维护人际关系"这件事在工作中占多少精力是你比较舒服的比例？多了一点还是会觉得累？
12. 如果一个岗位要求你同时跟技术团队、业务方、客户三方打交道，你觉得这是有意思的事还是纯粹的负担？
13. 你更喜欢跟少数几个人建立深厚的工作关系，还是在更大的圈子里保持广泛但不深的联系？
14. 当团队成员之间有矛盾的时候，你会自然地想去调解，还是觉得这不关你的事？
15. 你换工作时，"认识的人"这个因素对你有多重要？

### 战略思维域（8题）

16. 给你一个新的技术方向或者行业领域，你通常怎么入手？先广泛了解还是直接扎进某个具体问题？
17. 你觉得自己更适合做一个领域的专家（越钻越深），还是一个能串起多个领域的通才（广度优先）？
18. 做职业规划的时候，你更看重这个岗位能让你学到什么，还是更看重它现在的薪资待遇？
19. 面对两个offer，一个稳定但成长慢，一个风险大但成长快，你的直觉倾向哪一个？
20. 你平时会主动关注行业动态和技术趋势吗？还是更专注于手头的工作？
21. 如果让你负责一个新产品的方向规划，你觉得你的强项更多是在"想清楚做什么"还是"搞定怎么做"？
22. 你更相信数据分析得出的结论，还是更相信自己的直觉和经验判断？
23. 学一个新技术的时候，你喜欢先看系统性的教程/书，还是直接上手试错？

### 执行力域（7题）

24. 你觉得自己的工作节奏更接近哪种：每天都有明确计划按部就班，还是比较灵活随机应变？
25. 如果一个项目周期很长（半年以上），中间没有明确的里程碑反馈，你能保持动力吗？
26. 你更擅长从0到1把一件事搭起来，还是在已有的基础上优化改进？
27. deadline对你来说是动力的来源还是压力的来源？
28. 完成一个任务之后，你是那种马上开始下一个的人，还是会停下来复盘总结一下？
29. 你更喜欢独立完成一件完整的事，还是作为团队一部分贡献自己的环节？
30. 如果连续一周都在做一些琐碎重复的事情，你会觉得难以忍受还是可以接受？

## 三层Profile架构

```
┌─────────────────────────────────────────────┐
│  L1 基础自填层 (Base Profile)                 │
│  - 首次使用时通过5个核心问题快速建立           │
│  - 允许笼统回答、"不太确定"、跳过             │
│  - 结构: 四大领域各一段自由文本描述            │
├─────────────────────────────────────────────┤
│  L2 推断累积层 (Inferred Profile)             │
│  - 系统从历次JD分析的用户行为中提取            │
│  - 记录每次分析中的选择倾向信号                │
│  - 识别反复出现的吸引/排斥模式                 │
│  - 标记可能的自我认知偏差（行为vs自评不一致）   │
├─────────────────────────────────────────────┤
│  L3 校准权重层 (Calibration Weights)          │
│  - 用户对每次分析的"准/不准"反馈记录           │
│  - 基于反馈调整各维度的置信度                  │
│  - 校准日志: {日期, 分析ID, 维度, 判定, 备注}  │
└─────────────────────────────────────────────┘
```

## 首次填写引导流程

当检测到 `user-profile.md` 不存在时，进入首次引导：

1. **简短说明**（2-3句话）：告诉用户这是什么、为什么要填、数据只存本地
2. **5个核心问题**（从四大领域中精选，每个领域至少1个）：
   - "用一两句话描述一下你工作中最有成就感的状态"
   - "你理想中的工作节奏是什么样的？"
   - "你跟人打交道和跟事打交道，哪个更让你有能量？"
   - "做决定的时候你更信数据还是更信直觉？"
   - "你现在找工作最看重的三个因素是什么？"
3. **生成初始Profile**：将用户回答整理为结构化写入L1层
4. **明确告知**："这个画像会随着你以后每次分析JD逐渐丰富和校准，现在不用想太细"

## 每次分析后的渐进式提问规则

1. **时机**：在输出分析摘要和报告存档之后、对话结束之前
2. **数量**：严格限制2个问题，不超过
3. **选题策略**：
   - 从30条题库中选择与**本次岗位类型最相关的问题**
   - 优先选择尚未问过的问题（避免重复）
   - 如果所有问题都已问过，选择该用户之前回答较模糊/不确定的维度深挖
4. **话术风格**：自然嵌入对话，不要像问卷调查。"顺便问两句——"开头即可
5. **答案处理**：将用户回答追加到L2推断累积层的对应维度

## 反馈收集与校准协议

每次分析输出后，除上述2个渐进式问题外，还需收集匹配度反馈：

**标准反馈问句**：
> "以上分析里，哪些地方你觉得说得准？哪些跟你的实际情况不太一样？"

**校准处理规则**：

| 用户反馈类型 | 处理动作 |
|------------|---------|
| "某维度说准了" | 该维度置信度 +0.1，记录正向校准日志 |
| "某维度不准，实际我是..." | 用用户描述修正L2对应维度的推断值，记录修正校准日志 |
| "整体都还行" | 所有涉及维度置信度微调 +0.05 |
| "整体不太准" | 标记本次分析可能存在偏差，降低L1→L2映射权重 |
| 跳过/不回答 | 不做任何修改，保持现有状态 |

**自我认知偏差标记规则**：
- 当用户L1自评与L2行为推断连续2次以上出现方向性矛盾时，在Profile中标记该维度为"潜在偏差区"
- 后续分析中对偏差区的结论附加提示："这一点跟你之前的自评有些出入，你再感受一下"

## 维度到分野结论的映射

盖洛普四大领域的得分分布，映射到实际的岗位偏好分野：

| 分野维度 | 高影响力+高关系 | 高影响力+高战略 | 高战略+高执行 | 高执行+高关系 | 均衡型 |
|---------|---------------|---------------|-------------|-------------|-------|
| 客户导向 vs 内部协作 | 强客户导向 | 中偏客户 | 中偏内部 | 中偏内部 | 看岗位 |
| 社会资源 vs 个人能力 | 社会资源 | 混合（商业敏感） | 个人能力 | 混合（执行力+人脉） | 看岗位 |
| 快节奏 vs 深度研究 | 快节奏 | 中等偏灵活 | 稳定长跑 | 稳定协作 | 看阶段 |
| 商业敏感 vs 技术深耕 | 商业敏感 | 商业+战略 | 技术+落地 | 技术+协作 | 看岗位 |

注意：此表为指导性映射，最终结论需结合具体岗位类型的特征综合判断。
