# 跨项目一致性校验 Schema

## 校验时机

| 时机 | 触发条件 | 校验范围 |
|------|---------|---------|
| Phase 0 | 输出项目蓝图时 | 初步规划（项目数量、时间线分布、行业线索） |
| Phase 2 | **所有项目骨架全部出齐后** | 全量校验（时间线+行业+技术栈+角色+指标） |
| Phase 4 | 每个项目入库时 | 增量校验（新项目 vs 已入库项目） |

## 校验维度

```yaml
consistency_check:
  dimensions:
    - name: 时间线
      severity: 硬约束
      rule: >
        项目时间段不冲突（允许少量重叠，但需合理解释——
        如同一公司内部同时推进两个AI项目）。
        时间段之间不应有大段空白（>6个月）除非用户确认。
      check: "所有项目的 time_period 无矛盾重叠"
      on_fail: "提示冲突的时间段，建议调整"

    - name: 行业一致性
      severity: 硬约束
      rule: >
        所有项目应在同一行业或相关行业。
        跨行业需要用户自己提供转行叙事，系统不替用户编。
      check: "所有项目的行业标签属于同一行业族"
      on_fail: "标出跨行项目，提醒用户需准备转行叙事"

    - name: 技术栈递进
      severity: 软约束
      rule: >
        技术栈应体现成长趋势（如 LLM应用→RAG→Agent），
        但不死守线性递进。两个项目都用RAG但场景不同是允许的。
        先做Agent再补RAG基建也是合理的。
      check: "技术栈复杂度整体呈上升趋势"
      on_fail: "标出可能的倒退，询问用户是否有合理解释"

    - name: 角色递进
      severity: 软约束
      rule: >
        角色应体现成长趋势（参与→负责→主导→牵头），
        大方向要体现成长，但不必每个项目都升一级。
      check: "角色权责范围整体递增"
      on_fail: "标出可能的倒退，建议调整措辞"

    - name: 量化指标口径
      severity: 硬约束
      rule: >
        同行业不同项目的指标应使用一致的口径。
        如都用"准确率"则定义方式应一致（条款级 vs 合同级）。
      check: "同名指标的定义方式一致"
      on_fail: "标出口径不一致的指标，建议统一"

    - name: 公司规模一致性
      severity: 硬约束
      rule: >
        团队规模、数据量、预算与公司体量匹配。
        小公司不会有10人AI团队；大公司不会只有1个产品经理管所有AI项目。
      check: "团队/数据/预算在公司体量的合理范围内"
      on_fail: "标出不合理的数值，建议调整"

    - name: 信源可信度
      severity: 硬约束
      rule: >
        自洽不等于真实。每个项目须有一节 `## 信源分界`，
        标出 🟢原件直给 / 🟡有线索·数字待填 / 🔴零字全推演 三档，
        并单独点出**骨架级风险**（方向错了要整个重做的那一项）。
        须区分"数字级风险"（改数字即可）与"骨架级风险"（改骨架）。
        素材里没有该项目记录、仅凭口述推演时，必须在分界节开头直白说明源本身的问题。
      check: "每个项目均有信源分界，且骨架级风险已标出并进入核对清单第 1 位"
      on_fail: "要求补写分界节；并把骨架级风险提到核对清单首位、单独提示用户"
```

## 校验输出格式

```yaml
check_result:
  project_pair: [项目A, 项目B]  # 或 "全局"
  dimension: string
  severity: enum [硬约束, 软约束]
  status: enum [通过, 警告, 不通过]
  details: string               # 具体问题描述
  suggested_fix: string         # 建议的修改方式
```

## 展示方式

Phase 2 所有骨架出齐后，输出**跨项目对比表**：

```
项目    时间线          行业        技术栈      角色          关键指标
──────────────────────────────────────────────────────────────────
项目1   2023.06-12     建筑工程    LLM应用     参与→模块负责   准确率85%
项目2   2024.03-11     建筑工程    RAG+规则    主导           准确率90%
项目3   2025.01-至今   建筑工程    Agent       端到端负责      效率提升60%

✅ 时间线：无冲突
✅ 行业：一致（建筑工程）
✅ 技术栈：自然递进（LLM→RAG→Agent）
✅ 角色：成长趋势明显
⚠️ 指标：项目1和项目2都用"准确率"，建议确认是否同一口径
🔴 信源：项目1 无书面依据（素材里无该项目记录）→ 骨架级风险，需先确认经历是否存在
```

随后输出**信源分界总表 + 风险排序**（排序依据是"事实可核查性"，不是"推演比例"），
写入 `outputs/resume-framework.md`。格式见 `references/source-boundary.md`。
