# Phase 2: 一页纸骨架（每项目×1）

## 目标

基于 Phase 0 画像 + Phase 1 场景，为每个项目生成一页纸骨架。所有项目的骨架全部出齐后，统一做跨项目一致性复核。

---

## 骨架生成

### 输入

| 来源 | 提供什么 |
|------|---------|
| Phase 0 画像 | 年限、行业、交付模式、角色基调 |
| Phase 1 场景 | 场景名、差异化角度、技术时代 |
| 蓝图 | 该项目的时间段、技术栈约束 |
| calibration-rules.md | 校准规则 |

### 语言原则：业务先行

骨架的读者是面试官（可能是业务方、HR、或技术负责人），不是工程文档的读者。

1. **业务价值是主干**：每个项目骨架先讲"解决了什么业务问题、带来了什么收益"，技术是手段不是标题
2. **技术词必须有业务翻译**：出现技术术语时，必须在同一句或紧随其后用业务语言解释它在这个场景中做了什么。例：
   - ❌ "使用 LangGraph 编排 Multi-Agent 系统"
   - ✅ "拆成两个智能体协作——一个负责理解需求拆任务，一个负责看图匹配物料（LangGraph 编排）"
3. **项目名称以业务场景命名**：不用"XX AI 系统"，用"给谁做什么"的格式。例：
   - ❌ "Multi-Agent 智能识别系统"
   - ✅ "智能选材与设计协同平台"

### 生成规则

按 `schemas/project-skeleton.md` 的字段逐一生成：

1. **项目名称**：具体、有行业属性，以业务场景命名，不用"XX AI 系统"这种技术先行的通用名
2. **一句话定位**：≤30字，说清楚"给谁做""解决什么业务问题"，技术可提可不提，提则必须服务于业务理解。例：`给建材供应链做"图纸秒级转报价"的智能协同平台`（"秒级转报价"是业务价值，"智能协同"暗示 AI 但不堆术语）
3. **时间周期**：必须与蓝图中的时间段一致
4. **业务背景**：
   - `why_do_it`：从行业实际出发，含业务规模数据（处理量/人员数/频次）
   - `why_ai`：用业务语言论证为什么这个场景非 AI 不可——核心难点是什么（如"规则写不完、人工又慢又贵"），AI 能力怎么匹配这个难点。禁止用"提升效率""降低成本"等泛化表述，也禁止裸列模型名/框架名
5. **项目目标**：
   - 业务目标含具体数值
   - AI 目标含具体指标和数值预期
6. **角色**：必须与年限→叙事视角表一致
7. **交付模式**：继承画像，可按项目微调，描述具体的执行分工
8. **技术栈**：必须与时间线→技术栈匹配表一致
9. **团队构成**：含角色和人数，与公司体量匹配
10. **量化预期**：至少 2-3 个指标，含 before/after/improvement
11. **产品形态**：结构化描述产品的交付形态，避免后续全量生成时出现形态矛盾（如"无屏语音产品"却大篇幅讲 App UX）
12. **信源分界**：在骨架之后附一节 `## 信源分界`，按 🟢原件直给 / 🟡有线索·数字待填 / 🔴零字全推演
    三档归类，并标出**骨架级风险**（方向错则整个重做的那一项）。规则见 `references/source-boundary.md`

### 输出格式

```yaml
项目名称: [具体名称]
一句话定位: [≤30字]
时间周期: YYYY.MM - YYYY.MM
所在公司: [脱敏名称]

业务背景:
  为什么要做: [含业务规模数据]
  为什么用AI: [场景的 AI 适配性论证]

项目目标:
  业务目标: [含具体数值]
  AI目标: [含指标和数值预期]

你的角色: [基于年限校准]
交付模式: [执行分工描述]

技术栈: [与时间线匹配]
团队构成: [角色×人数]

产品形态:
  交互入口: [集成进已有平台(ERP/OA/CRM) / 独立门户或App / 插件(飞书/钉钉/企微/浏览器) / API/SDK(无直接UI) / 硬件终端(大屏/手持/语音)]
  AI角色: [AI原生(AI是核心，无AI产品不存在) / AI增强(已有产品加AI能力) / AI后台(用户无感知)]
  部署形态: [SaaS多租户 / 私有化部署 / 混合部署 / 端侧运行]
  与现有系统关系: [替代旧系统 / 增强旧系统 / 全新业务线]

预期量化成果:
  - [指标1]：[before] → [after]（[improvement]）
  - [指标2]：[before] → [after]（[improvement]）
  - [指标3]：[描述性成果]
```

### 骨架之后必须紧跟：信源分界

骨架是"要讲的内容"，信源分界是"哪些内容有依据"。**两者必须写在同一份 `skeleton.md` 里**，
否则用户和下游 skill 都无从分辨。格式与判定规则见 `references/source-boundary.md`。

```markdown
## 信源分界（哪些是原件里的，哪些是我推的）

**素材原文（[素材文件名] 第 N 条）：**

> [原文摘录，一字不改]

| 档位 | 内容 |
|---|---|
| 🟢 **原件直给（可直接讲）** | [能指到原文的] |
| 🟡 **原件有线索、数字由我填** | [素材提到的方向 → 推演出的量级] |
| 🔴 **原件零字、全部推演** | [素材完全没有的] |

> ⚠️ **[最高风险项]**：[一旦不符需整体重做的那一项]
```

**两种核对要分开**：数字级（骨架对、数值待替换，🟡）vs **骨架级**（方向本身是推演，不符则整个项目重做，🔴）。
骨架级风险优先提到「真人核对清单」第 1 位。

### 角色职能嵌入（3 年+候选人适用）

如果候选人年限 ≥3 年，骨架生成时需检查 `calibration-rules.md` §9 的角色职能维度表，
看该项目的场景/交付模式是否天然涉及某些职能项（如 ToB 项目涉及售前、客户经营）。
若涉及，在骨架的 `你的角色` 和 `交付模式` 字段中**留出职能锚点**，
Phase 3 全量生成时在对应阶段展开讲。

例：骨架写"角色：AI 产品经理（兼售前技术支持，负责 3 家核心客户的需求对接与方案宣讲）"
→ Phase 3 的 Stage 1 立项就会展开售前环节，Stage 6 就会展开客户续约。

### 用户确认

```
这是 [项目名] 的一页纸骨架，请检查：

[骨架内容]

你可以修改任何字段。确认后我们继续下一个项目的场景选择。

⚠️ 注意：所有项目的骨架全部完成后，我会做一次跨项目统一复核。
```

## 统一复核（所有骨架出齐后触发）

### 触发条件

当蓝图中规划的所有项目都完成了骨架生成且用户确认后，自动触发统一复核。

### 复核内容

按 `schemas/consistency-check.md` 的维度逐一检查：

1. **输出跨项目对比表**：

```
项目    时间线          行业        技术栈      角色          关键指标
──────────────────────────────────────────────────────────────────
项目1   YYYY.MM-MM     XX行业     [技术A]     [角色A]       [指标A]
项目2   YYYY.MM-MM     XX行业     [技术B]     [角色B]       [指标B]
项目3   YYYY.MM-至今   XX行业     [技术C]     [角色C]       [指标C]
```

2. **逐维度校验结果**：

```
✅ 时间线：无冲突
✅ 行业：一致（XX行业）
✅ 技术栈：自然递进
✅ 角色：成长趋势明显
⚠️ 指标：项目1和项目2都用"准确率"，请确认是否同一口径
🔴 信源：项目1 无书面依据（素材里没有该项目的记录），存在骨架级风险
```

3. **信源分界总表**（新增，必须输出）：

在 `outputs/resume-framework.md` 中汇总三个项目的真实/推演分界 + **风险排序**
（排序依据是"事实可核查性"，不是"推演比例"）。格式见 `references/source-boundary.md`。

4. **用户确认**：

```
以上是所有项目的一致性复核结果。

[如有警告] 有以下需要你确认的点：
- [警告1的具体说明]
- [警告2的具体说明]

确认后，我会先出一版简历框架，然后逐个项目生成全量细节。
```

## 触发简历框架

统一复核通过后，**在进入 Phase 3 之前**，先输出简历框架。

### 骨架阶段能出的内容

| 内容 | 来源 |
|------|------|
| 简历整体结构（板块 + 排列顺序） | 写作体系 + 年限 |
| 个人简介方向（职业主线初稿） | 行业线索 + 跨项目主线 |
| 项目列表和排序 | 蓝图中的项目序列 |
| 教育经历、基础信息 | Phase 0 画像 |

### 骨架阶段出不了的内容（占位）

| 内容 | 需要等什么 |
|------|-----------|
| 每个项目的详细项目段 | Phase 3 全量生成 |
| 个人简介定稿 | 全量生成后的能力证据 |
| 技能清单 | Phase 4 自动提取 |
| HTML 精排版 | 所有文本内容完成后 |

### 简历框架输出

```
简历框架（骨架版）
─────────────────────────────────────────
[姓名] | [手机] | [邮箱]

个人简介（方向稿，全量完成后定稿）
  X年XX行业产品经理经验，聚焦XX领域的AI产品落地...
  [待补充：核心能力证据、代表成果数据]

项目经历
  项目1：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]
  项目2：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]
  项目3：[项目名]（YYYY.MM-YYYY.MM）
    [占位：Phase 3 完成后填入]

教育经历
  [学校] | [专业] | [学历] | [毕业年份]

技能清单
  [占位：Phase 4 入库后自动提取]
─────────────────────────────────────────
```

## Phase 2 完成条件

| 条件 | 说明 |
|------|------|
| 所有骨架已生成 | 蓝图中规划的每个项目都有骨架 |
| **每份骨架含信源分界** | 三档归类 + 骨架级风险已标出（见 `references/source-boundary.md`） |
| 所有骨架用户已确认 | 用户逐个确认或修改后确认 |
| 统一复核通过 | 跨项目一致性无硬约束违规 |
| **信源分界总表已输出** | 含风险排序，写进 `outputs/resume-framework.md` |
| 简历框架已输出 | 用户看过框架（不需要确认，仅展示） |

完成后，进入 Phase 3（逐个项目生成全量细节）。
